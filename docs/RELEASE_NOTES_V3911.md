# v3.9.11 — Spectrum signature stability / Review continuation

## What changed

Fix an additional confirmed cause of false Sampling v6 read-only. Repeated
imports of unchanged audited Spectrum source can produce different marshal
bytes for equivalent normalized code objects, reproduced on Python 3.13.12.
The legacy audit remains first. Only differences confined to function code
digests can invoke fixed Python 3.12/3.13 supplemental profiles; all loaded
descriptors, source hashes, provenance, defaults, closures and runtime state
must still pass. Unknown or modified code remains non-reusable.

The original four provider metadata files and persisted Sampling v6 identity
are unchanged. Four genuine pre-repair safe v6 Take fixtures retained identical
full contracts and reused their saved Chunk 1. Old unsafe/v5 Takes stay readable
and read-only; no flags or manifests are rewritten. Public node IDs, inputs,
widget order, Graph v4, Run Storage and official workflow JSON/ZIP bytes remain
unchanged. No provider import, profile generation or identity learning occurs
in the runtime audit.

## Update and check

Update the existing copy through ComfyUI Manager, or replace the custom-node
package in `ComfyUI/custom_nodes/ComfyUI-H3-Continuum`. For a Git installation,
update that same folder from main. Avoid duplicate installations. **Fully restart
ComfyUI and hard-refresh the browser with Ctrl+F5.** Keep existing Takes,
workflows and model files.

Use a **new, unique Run Name**, enable Spectrum and Review Each Chunk, and
generate Chunk 1. Select its new Take in Render History; check Use This Take /
Continue From Here, then continue to Chunk 2. Existing read-only Takes are not
automatically made reusable. No workflow rewiring or Take deletion is required.

## Separate MP4 menu-thumbnail workaround

Custom Scripts' Show Image On Menu can request an MP4 through Core's image
preview endpoint, causing an HTTP error despite successful generation and valid
video files. If encountered, search Settings for **Show Image On Menu** and
turn it **OFF**. A browser load/save of an existing MP4 after this setting change
produced **zero new thumbnail HTTP errors**. The test performed no new inference.
This is a separately verified setting workaround, not a Continuum/Core/Custom
Scripts code change; this update does not alter the setting automatically.
